# Wio Memo 产品需求文档（PRD）

| 字段 | 内容 |
|---|---|
| 产品名称 | Wio Memo 桌面备忘录 |
| 文档版本 | v0.1 Draft |
| 目标硬件 | Seeed Studio Wio Terminal |
| 目标版本 | MVP v1.0 |
| 产品形态 | 桌面常亮终端 + 局域网 Web 管理端 |

## 1. 背景与问题

用户的任务和会议通常保存在电脑或手机中，但桌面工作时容易被窗口、通知和手机干扰淹没。Wio Memo 提供一个独立、低干扰、始终可见的桌面终端，让用户通过电脑浏览器快速维护事项，并在关键时间通过屏幕与声音获得提醒。

## 2. 产品目标

1. 用户在同一局域网内，30 秒内完成一条待办或会议的创建。
2. 设备断网后仍能显示已同步事项，并按 RTC 时间正常提醒。
3. 到达提醒时间或开始时间后，设备在 1 秒内显示提醒状态并发出提示音。
4. 用户无需打开手机 App，即可在设备上查看下一事项、完成待办、静音或稍后提醒。

## 3. 非目标（MVP 不做）

- 不提供公网直接访问和多账号协作。
- 不对接企业微信、钉钉、飞书、Outlook 或 Google Calendar。
- 不支持复杂项目管理、子任务、附件和评论。
- 不承诺在设备屏幕直接输入文本。
- 不把 Wio Terminal 暴露到公网，也不在设备上实现完整 TLS 账号系统。

## 4. 目标用户与核心场景

### 4.1 目标用户

- 长时间在固定工位工作的开发者、设计师、学生和办公室人员。
- 希望减少手机干扰，但不能错过会议和重要任务的人。

### 4.2 核心场景

1. 用户上班后打开 `http://wio-memo.local`，添加今天的待办。
2. 用户创建 14:00 的会议，设置提前 10 分钟提醒。
3. 13:50 设备进入提醒页并响两声；14:00 再次响两声。
4. 用户按五向键确认提醒，或选择稍后 5 分钟。
5. Wi-Fi 暂时中断，设备继续使用 RTC 显示和提醒已有事项。

## 5. 信息模型

### 5.1 事项 Task

| 字段 | 类型 | 规则 |
|---|---|---|
| id | uint32 | 设备内唯一 |
| type | enum | `todo` / `meeting` |
| title | UTF-8 string | 1–48 字节；MVP 屏幕需完整中文支持后再开放任意中文 |
| startAt | Unix seconds UTC | 必填 |
| endAt | Unix seconds UTC/null | 会议可选；待办为空 |
| remindBefore | minutes | 0/5/10/15/30/60 |
| status | enum | pending/completed/cancelled |
| alertState | bit flags | 提前提醒、开始提醒、确认状态 |
| updatedAt | Unix seconds UTC | 用于同步冲突处理 |

### 5.2 设备配置 DeviceConfig

设备名称、Wi-Fi SSID/凭据、时区、静音状态、音量、默认提醒时间、屏幕亮度、NTP 服务地址。

## 6. 功能需求

### P0：MVP 必须完成

| 编号 | 需求 | 验收条件 |
|---|---|---|
| P0-01 | 首次配网 | 无配置时启动热点；浏览器输入 SSID/密码及时区；重启后自动联网 |
| P0-02 | Web 事项管理 | 可新增、编辑、删除、完成待办和会议；错误有明确反馈 |
| P0-03 | 设备事项列表 | 展示当前时间、最近 4 条未完成事项、类型和开始时间 |
| P0-04 | 时间同步 | 联网后 NTP 校时；每 6 小时重校；断网继续走 RTC |
| P0-05 | 提醒 | 提前提醒和开始提醒各只触发一次；重启后不得无条件重复响铃 |
| P0-06 | 提醒操作 | 五向键支持确认、完成、稍后 5 分钟；C 键静音/恢复 |
| P0-07 | 持久化 | 断电重启后任务、配置、提醒状态保持；损坏数据安全回到默认状态 |
| P0-08 | 中文显示 | 常用中文标题可显示、换行和省略，不出现乱码 |
| P0-09 | 网络恢复 | Wi-Fi 断开后自动退避重连，不阻塞屏幕和提醒循环 |
| P0-10 | 安全边界 | 配网接口仅在 AP/配网模式开放；管理 API 至少支持本地访问口令 |

### P1：MVP 后增强

- 重复任务、全天事项、分类和优先级。
- 浏览器搜索、筛选、批量完成。
- microSD 备份/恢复和日志导出。
- OTA 升级和固件版本检查。
- CalDAV/ICS 导入或局域网同步服务。

## 7. 关键交互规则

- 首页默认突出“下一项”，列表按未完成优先、开始时间升序排列。
- 提醒弹出时覆盖普通列表，但保留当前时间、事项标题和三个明确动作。
- 声音默认两短声；提前提醒与开始提醒使用不同节奏，避免混淆。
- 静音只关闭声音，不关闭屏幕提醒；界面始终显示静音标志。
- Web 保存成功后设备屏幕应在 2 秒内更新。
- 已过期但未完成的任务标记为“已逾期”，不会每秒重复响铃。

## 8. 非功能需求

| 类别 | 指标 |
|---|---|
| 启动 | 上电 5 秒内显示本地数据；联网过程不能白屏 |
| 响应 | Web API 在局域网正常情况下 500 ms 内响应；按键反馈 100 ms 内可见 |
| 稳定性 | 连续运行 7 天无死机；网络断连不影响本地提醒 |
| 资源 | RAM 峰值不超过 75%；Flash 不超过 80% |
| 存储寿命 | 合并写入并避免周期性无变化写 Flash |
| 可恢复性 | 看门狗恢复；异常重启后存储数据可校验 |
| 可访问性 | Web 支持键盘操作、窄屏布局和明确错误文本 |

## 9. MVP 成功指标

- 20 次创建/编辑/完成操作全部正确同步到设备。
- 50 次设定时间提醒的触发误差不超过 ±1 秒，且无重复触发。
- 断网、重连、重启、断电四类场景的关键数据不丢失。
- 5 名试用者中至少 4 名无需指导即可完成配网、添加会议和静音。

## 10. 待产品确认的问题

1. 首版是单用户局域网设备，还是必须支持公网/手机外网编辑？
2. 中文字库优先采用 microSD 完整字库，还是固件内置常用字库？
3. 提醒需要“确认/稍后提醒”，还是只响一次即可？
4. 待办是否必须有时间，还是允许只有日期或完全无截止时间？
5. 是否需要导入 Outlook/Google/飞书日历？这会显著改变后端和授权架构。
