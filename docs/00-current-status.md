> 更新日期：2026-08-04

## 状态说明

- **已验证**：有构建、自动测试或实机结果支持。
- **已实现，待回归**：代码路径存在，但最新版本尚未完成完整实机回归。
- **实验性**：代码或接口存在，尚不作为稳定产品能力宣传。
- **未实现**：规划项，不应写成现有功能。

## 当前稳定性选择

默认构建使用协作式主循环处理 UI、无线状态机、Web 和天气请求。仓库保留 FreeRTOS UI/网络双任务实现，但 `SAFE_UI_ONLY_MODE` 当前为启用状态，因此默认固件并不依赖双任务运行。这一选择来自前期 Wi‑Fi 切换造成界面卡死的实机问题。

## 已知限制

- 最新提交尚未写入实机，原因是上一次上传时电脑没有枚举到串口。
- 天气城市当前固定为深圳；没有面向用户的城市设置页。
- AQI 不属于当前稳定天气链路。
- 网络请求仍受 `rpcWiFi` 行为影响，不能宣称已经完成 7×24 小时稳定性验证。
- Web 没有账号、口令或 TLS，且状态接口当前会返回 AP 密码，只能用于可信局域网。
- Web 支持新增、完成、删除和整表保存，不支持复杂逐项编辑、重复任务或日历导入。
- 固件 Flash 已接近 90%，新增 TLS、图片、字体或游戏前必须先做体积优化。

## 下一轮验收顺序

1. 写入最新固件，逐页验证深圳中英文标题、实时天气、秒钟时钟和摇杆操作。
2. 连续执行 STA → AP → STA → 离线切换，记录 IP、网页响应和 UI 帧率。
3. 使用错误密码、路由器断电、外网不可用三种场景验证超时与恢复。
4. 验证 12 条事项、提前提醒、准时提醒、静音、重启去重和断电恢复。
5. 进行至少 24 小时运行观察，再决定是否扩大到 7 天稳定性测试。
